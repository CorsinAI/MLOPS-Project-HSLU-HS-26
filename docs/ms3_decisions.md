| 45 | 2026-11-26 | A stored feature row for day D is frozen at gate closure, 12:00 Berlin on D-1. After that it is never rewritten, complete or not. A row that was never stored may still be written later, for example by a backfill. Each row stores `fetched_at`, the UTC time its run fetched the sources. Features move to version 2; version 1 stays as it is. Only the decision whether to write uses the clock; the values are still selected by timestamp. | A1 (Must): the training table must show what serving saw. Gate closure, not the cut-off, because inference rebuilds the row between 10:00 and 12:00 and predicts from that row. A row written before 10:00 still misses data that counts as available by 10:00. `fetched_at` after gate closure marks a rebuilt row, so training can tell rebuilt rows from live ones. |

| 48 | 2026-11-26 | Inference has no cron. It runs by `workflow_dispatch`, by hand or from an external trigger. Options: an external scheduler that calls `workflow_dispatch` at 10:05 Berlin (for example Google Cloud Scheduler, which takes a time zone, so the clock changes need no second cron line), or Apache Airflow, which needs a host that runs all the time. MLflow tracks runs and models; it does not schedule. | E1 (Must): the entry point and the guard work with any trigger. The choice is the owner's. |
